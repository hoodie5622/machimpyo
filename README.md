# 마침표

제출 전에 **파일명·누락·확장자·개수·용량**을 확인하는 한국어 웹앱입니다. 사람이 정리하고 확정한 기준과 사용자가 선택한 파일 정보를 비교합니다.

HTML, CSS, JavaScript ES modules로 구현했습니다. 로그인, 서버 API, 데이터베이스, 외부 라이브러리 없이 실행합니다. 기존 작업 폴더의 다른 프로젝트는 수정하지 않았습니다.

## 웹에서 사용하기

GitHub Pages 배포 주소: **https://hoodie5622.github.io/machimpyo/**

브라우저에서 주소를 열어 사용합니다. 설치나 로컬 서버 실행이 필요하지 않습니다. 기준은 접속한 브라우저에 저장하며, 선택한 제출 파일은 업로드하지 않습니다.

로컬 주소에서 저장했던 기준은 웹 주소로 자동 이전되지 않습니다. 로컬 앱에서 JSON으로 내보낸 뒤 웹 앱에서 가져오세요.

`main` 브랜치에 변경 내용을 올리면 GitHub Actions가 테스트 후 앱 실행 파일만 다시 배포합니다. 배포 파일은 `index.html`, `styles.css`, `js/`, `data/`이며 로컬 서버와 테스트 파일은 웹사이트 배포 산출물에 포함하지 않습니다. 배포 설정은 `.github/workflows/pages.yml`입니다.

## 실행하기

1. 이 폴더의 `start.cmd`를 두 번 클릭합니다.
2. 명령 창을 열어 둔 채 브라우저에서 **http://127.0.0.1:4187/** 을 엽니다.
3. 사용을 마치면 명령 창에서 `Ctrl+C`를 누르거나 창을 닫습니다.

Node.js가 필요합니다. 이 컴퓨터에서는 **Node.js v24.18.0**으로 실행·검증했습니다. 별도 패키지 설치는 필요하지 않습니다.

PowerShell에서 실행하려면:

```powershell
git clone https://github.com/hoodie5622/machimpyo.git
Set-Location machimpyo
npm start
```

`node server.mjs`도 같은 서버를 실행합니다. `index.html`을 직접 더블클릭하는 방식은 ES modules 제약이 있으므로 사용하지 마세요.

4187 포트가 이미 사용 중이면 다른 포트를 선택할 수 있습니다.

```powershell
$env:MACHIMPYO_PORT = '4190'
npm start
```

이때는 서버가 출력한 주소를 엽니다. 주소나 포트가 다르면 브라우저 기준 저장소도 달라집니다. 개발 검증에 사용한 임시 서버는 종료했습니다.

## 처음 사용하기

1. **예시 기준으로 시작**을 누릅니다. 실제 학교 규정이 아닌 가상 예시입니다.
2. 조건과 원문을 읽고 **이 기준으로 검사하기**를 누릅니다.
3. 학번·이름을 입력하고 제출 파일을 고릅니다. 학번의 앞자리 `0`을 유지합니다.
4. 각 파일의 문서 역할을 직접 지정합니다. 파일명으로 역할을 자동 확정하지 않습니다.
5. **파일 검사**를 누르고 요구 값·실제 값·다음 행동을 확인합니다.
6. 파일을 수정했다면 앱에서 다시 선택하거나 **교체**한 뒤 재검사합니다.
7. 서명·내용 등 **직접 확인** 항목은 사람이 확인한 뒤 체크합니다.
8. 실제 제출은 원래 제출처에서 직접 진행합니다.

검사 결과는 `통과`, `수정 필요`, `미검사`, `해당 없음`으로 나눕니다. 앱 기본 점검과 기준의 자동 규칙도 별도로 표시합니다. 파일·역할·이름·기준이 바뀌면 이전 결과는 **다시 검사 필요**가 되고 수동 체크는 초기화됩니다.

## 자기 기준 만들기

**새 기준 만들기**에서 제목, 원문, 역할, 자동 조건, 직접 확인 항목을 작성합니다.

- 각 역할에는 파일 개수 조건이 정확히 하나씩 필요합니다. 예를 들어 필수 한 개는 최소 1·최대 1, 선택 항목은 최소 0으로 설정합니다.
- 확장자는 점 없이 쉼표로 구분합니다. 예: `pdf, hwp, hwpx`.
- 용량은 MB 또는 MiB를 선택합니다. `4.10 MB`는 정확히 **4,100,000바이트**입니다. MiB 환산에서 바이트 미만은 버립니다.
- 파일명은 `{studentId}_{name}_보고서.pdf`처럼 고정 확장자를 포함한 전체 이름을 씁니다. 자리표시자 버튼으로 학번과 이름을 넣을 수 있습니다.
- 각 조건에 **원문 발췌** 또는 **작성자 추가 기준**의 근거를 적습니다. 발췌는 원문에 실제 포함된 문장이어야 합니다.
- 미완성 내용은 **초안 저장**으로 보관합니다. 초안은 검사·공유에 사용할 수 없습니다.
- **기준 확정**을 누르면 검증 후 저장합니다. 오류가 있으면 해당 필드와 이유를 안내합니다.

확정본을 편집하면 작업용 초안이 생깁니다. 변경된 내용을 확정하면 같은 기준의 버전이 올라가며 최근 이전 확정본 하나를 보관합니다. 내용 변경이 없으면 버전을 올리지 않습니다. 현재 검사 중인 기준은 사용자가 새 버전을 확인·적용하기 전까지 바뀌지 않습니다.

## 기준 공유하기

확정 기준의 **내보내기**에서 공유할 내용을 확인하고 JSON을 저장합니다. 다른 브라우저에서는 **기준 가져오기**로 파일을 선택하고 미리보기를 검토한 뒤 저장합니다.

- 기준 JSON 한도는 UTF-8 기준 **256KiB**입니다.
- 같은 ID·버전·내용이면 중복 추가하지 않습니다.
- 더 높은 버전은 변경 내용을 확인한 후 갱신하거나 사본으로 가져옵니다.
- 같은 버전의 다른 내용 또는 오래된 버전은 새 ID·v1의 사본으로만 가져올 수 있습니다.
- 지원하지 않는 필드·규칙·자리표시자, 잘못된 참조·범위·발췌는 거부합니다.
- 검증이나 저장이 실패하면 기존 기준과 검사 세션을 유지합니다.

내보내는 파일에는 기준과 공지 원문이 포함됩니다. 원문 자체에 개인 정보가 있으면 공유 전에 확인하세요. 현재 세션의 이름·학번, 선택 파일, 검사 결과는 자동으로 포함하지 않습니다. 앱은 발행자 인증이나 전자서명을 제공하지 않습니다.

## 저장과 파일 처리

확정 기준·최근 이전 버전·초안만 현재 브라우저에 저장합니다. 파일, 파일 정보, 이름·학번, 검사 결과, 직접 확인 표시는 영구 저장하지 않습니다. 새로고침하면 파일을 다시 선택해야 합니다.

전용 키는 `machimpyo:v1:templates`, `machimpyo:v1:settings`입니다. 마침표 초기화는 이 두 키만 지우며 다른 앱의 데이터를 지우지 않습니다. 손상된 저장 데이터는 자동으로 덮어쓰지 않고 원문 보관·다시 읽기·명시적 초기화를 제공합니다.

다른 탭에서 기준이 바뀌면 편집 중인 초안을 보존하고 덮어쓰기를 거부합니다. 사본 초안으로 저장할 수 있습니다. 다중 탭 저장은 완전한 원자적 트랜잭션을 보장하지 않으므로 한 탭에서 편집하는 것을 권장합니다.

선택 파일의 원본은 변경하지 않습니다. 파일 본문을 읽거나 업로드하지 않고 File 객체의 이름·크기 등 메타데이터만 검사합니다. 앱에는 네트워크 호출 코드와 제출 API가 없으며 `connect-src 'none'` 정책을 적용했습니다. 출처 주소도 자동으로 불러오지 않습니다.

## 파일별 역할

- `index.html`, `styles.css`: 앱 시작점, 화면 스타일, 반응형 배치와 상태 색상.
- `js/app.js`: 화면 이동, 파일 선택, 가져오기·내보내기, 각 모듈의 연결.
- `js/render.js`: 입력을 HTML로 실행하지 않는 안전한 DOM 생성, 공통 입력·대화상자·다운로드.
- `js/editor.js`: 역할·자동 규칙·근거·직접 확인을 작성하는 양식.
- `js/rules.js`: 파일 메타데이터를 기준과 비교하는 순수 검사 함수 및 요약.
- `js/state.js`: 세션, 입력 변경, 수동 체크, 검사 스냅샷과 오래된 결과 차단.
- `js/files.js`: 최대 30개 파일 추가, 역할 지정, 제거·교체, 검사 정보 생성.
- `js/utils.js`: ID, 확장자·파일명 처리, 정확한 MB/MiB 환산.
- `js/templates.js`: 엄격한 JSON 검증, 초안·확정·버전 비교와 충돌 분류.
- `js/storage.js`: 전용 키 읽기·쓰기, 손상·저장 실패·다른 탭 변경 감지.
- `data/example-template.js`: 기획서의 가상 예시 기준.
- `server.mjs`, `start.cmd`, `package.json`: 설치 없이 실행하는 로컬 정적 서버와 실행 명령.
- `tests/`: 자동 테스트, 가상 검사 파일, 브라우저 수동 확인 안내와 좁은 화면 확인 페이지.
- `VERIFICATION.md`: 실제 수행한 검증과 아직 확인하지 않은 범위.
- `PROGRESS.md`: 기획서 개발 단계 M0~M4의 진행 기록.

## 검증하기

```powershell
npm test
```

2026-11-13 검증 결과: **78개 통과, 실패 0개, 건너뜀 0개**. Node.js 내장 테스트를 사용합니다. 바이트 경계, Unicode 파일명, 필수·선택 역할, 수동 체크와 결과 무효화, 늦은 실행 결과 차단, JSON 안전성·버전 충돌, 저장 실패·손상·다중 탭 충돌, 정적 서버 동작을 확인합니다.

실제 브라우저에서 파일 선택·교체·역할 지정·검사·재검사, 기준 작성·저장·확정, JSON 다운로드 후 재가져오기, 잘못된 JSON 거부, v2 갱신과 적용, 두 탭의 충돌·사본 저장, 새로고침, 320px·360px iframe 화면을 확인했습니다. 자세한 결과와 검증 한계는 `VERIFICATION.md`에 적었습니다.

브라우저 수동 확인 안내: **http://127.0.0.1:4187/tests/**

가상 검사 자료를 다시 생성하려면:

```powershell
node tests/create-fixtures.mjs
```

`tests/fixtures/`의 PDF 확장자 파일은 **실제 PDF가 아닙니다**. 메타데이터 판정용 가상 자료이므로 문서 내용이나 서명 확인에 사용하지 마세요. 브라우저 검증 과정에서 이 출처에 저장한 가상 기준·사본 초안이 남아 있을 수 있습니다.

## 현재 한계

본문 내용·실제 파일 형식·문서 손상·서명·PDF 페이지 수·압축 내부는 검사하지 않습니다. 외부 폴더 수정이나 공지 갱신을 자동 감지하지 않습니다. 같은 이름의 파일도 각각 선택 항목으로 세며 내용 중복을 판단하지 않습니다.

계정, AI/OCR, 서버 저장, 기기 동기화, 자동 파일 변환·이름 변경·제출은 포함하지 않습니다. 시간 절감률이나 오류 감소율 등의 사용자 효용은 측정하지 않았습니다.
